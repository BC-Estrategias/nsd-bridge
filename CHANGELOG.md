# Changelog

## 2.0.0 — Titles, Translations and Mods, much faster internet downloads
- **Titles (3DS).** A new **Titles** screen lists what is installed on the console, like FBI's, with the icon, name, ID, size and version of each title. Filters: games, updates and DLC, DSiWare, apps, system, all. Each title can be launched or deleted after a confirmation (titles on the SD card and DSiWare can be deleted, optionally with their ticket; NSD Bridge itself and the rest of system memory cannot). The list of pending (half-installed) titles is there too. The first read is saved to `cache/titles.bin`, so the next time it opens at once.
- **Translations (3DS).** Installs fan translations published as Luma3DS *LayeredFS* patches (`/luma/titles/<ID>/…`) from a Nextcloud public link, laid out as `traducoes/<language>/<ID - game>/<team>/<version>/` (see `docs/translations.md`). The list shows `★` for what NSD Bridge installed (`↑` when the share has a newer version, `!` for an install that did not finish) and `☆` for a folder put there by hand. Install, update, reinstall and uninstall; the confirmation screen shows the files, the size, the team, the region, a warning when the game is not installed on this console, and an optional description and status written by the pack's author. Every file path is checked before anything is written (relative only, no `..`, no odd characters), files are fetched six at once over one kept-alive HTTPS connection, a file that fails with a server error or a dropped connection is tried again up to three times, and a record in `/luma/titles/<ID>/.nsd-pack.json` makes the uninstall remove exactly what was installed. This build carries a default **read-only** link to BC Labs' share; **SELECT** in the screen changes it (type `-` to go back to the default).
- **Mods (3DS).** The same engine for a second catalog, `mods/<ID - game>/<mod>/<version>/`. A mod may replace files that already exist (a code patch, for example), so before it writes, the originals are copied to `/luma/titles/<ID>/.nsd-backup/<mod>/`: the confirmation says how many files will be replaced (and how many belong to another installed pack), a failed install rolls back, and uninstalling puts the originals back.
- **The catalog refreshes itself.** The saved list appears at once when Translations or Mods opens, and one small request asks the share whether anything changed (its folder tag); if so the list is read again, otherwise nothing more happens. If the server does not answer, a red line says **the server is down (HTTP code)** and the saved list stays usable; the failure screens name a down server instead of a curl code. **Y** still forces a full read.
- **Internet downloads are 5 to 25 times faster.** The console's default TCP receive window (about 8 KiB) capped every connection at window ÷ round-trip time. Every connection now asks for 56 KiB and the socket service gets 4 MiB (1 MiB if memory is short). A computer on the same network was never affected; a CIA or a pack from a server far away was. The table of what was measured is in `agent/3ds/source/nettune.h`.
- **Installer fixes.** HOME works while a download is running (it is switched off only from the moment the system's title manager holds an install open, which is what hangs the console). **Closing the app during a download now keeps the pieces for a resume** (the weekly clean-up of old partial downloads trusted a file date that the card does not give, so it deleted them every time the app started). B still throws them away.
- **Menu:** Updates, Settings (folders, mode, pairing, log), Titles, Translations, Mods, Installer. The seeds row only shows when `/fbi/seed` exists. START leaves from the main menu.
- Host tests added for the WebDAV listing, the pack names and paths, the version order, the `pacote.json` reader, UTF-16 names and the piece map of the downloader.
- **Known limits.** The card is slow at creating files (about 8 to 9 per second): a pack of tens of thousands of files takes a while, and uninstalling one is slow too. A translation is written straight to its final name (the record says "incomplete" until the end), a mod still uses a temporary name and a rename because it may be replacing a backed-up file. The catalog reader understands Nextcloud / ownCloud public links only.

## 1.8.3 — HOME freeze fix, downloads in pieces with resume
- **Fixed: the HOME button froze the console** (1.8.2). The app kept the screen-backlight service open all the time (added in 1.8.2 to turn the screens off while installing), and that made the console hang when HOME was pressed. The service is now opened only while a screen is actually off during an install, and closed again as soon as the screens wake. If you are on 1.8.2, update.
- **Downloads in pieces, with resume.** When the file's size is known and the server honours HTTP `Range` (the console checks), the install first downloads to `/3ds/nintendo-dev-agent/downloads/` using 4 connections that fetch 1 MiB pieces, then installs from that file, with the same size and SHA-256 checks as before. If the download is interrupted (Wi-Fi, battery, closing the app), the same URL continues where it stopped: the confirmation screen says how much is already on the card. A small map file records which pieces are complete; a piece is only counted after it was written in full, and a changed file (size or the server's ETag / Last-Modified) starts over. Pressing B (cancel) deletes the partial download; partial downloads older than 7 days are deleted at start; the Installer menu has **Clear partial downloads** (shows how many and how big). If the server does not honour `Range`, the card does not have room for the file plus the installed copy, or the file is over 4 GiB, the installer streams straight into the system as before (no resume). Measured on a real console against a computer on the same network: a 15 MiB CIA in 37 s of download (the Wi-Fi radio's limit is about 0.45 MiB/s), then 13 s to install; an interrupted download resumed with the pieces already there and installed with the same SHA-256.
- The speed test (`#speedtest` on a URL) now compares 1, 2, 4 and 8 connections and logs the curl error when a variation fails.
- **Battery:** the level shown no longer jumps (a reading of 100% between 78% ones was seen while charging); it moved from the header, where it covered the version, to the line below it.

## 1.8.2 — installer: seeds, speed, battery
- **Seeds (the game-key that newer eShop titles need to open).** Before downloading, the console asks Nintendo's seed server whether the title has one and says so on the confirmation screen (seed available / the server has none / could not check). After the install the seed is registered, taken from, in this order: the request (new optional **Seed** field on the web page and `ndev install --seed`), `/fbi/seed/<TITLE_ID>.dat` on the card, or Nintendo's server. This fixes games that installed but crashed when opened. Create `config/no-seed-download` to turn the server lookup off. The seed server's certificate comes from a private Nintendo CA, so after a verified attempt fails the console makes one unverified retry for that fixed host and path only.
- **Progress:** speed, **time left** and the **SHA-256** (shown on two lines when done) are on screen; the log gets short lines with the average speed, the system's write time and the full hash. The web page has an optional **SHA-256** field next to the URL.
- **Download speed:** the data now goes to the system through a 4-slot pipeline (a download thread fills 128 KiB blocks, a writer thread writes them), covered by host tests including a thread-sanitizer run. A speed test (`#speedtest` on the URL) showed the limit on this console is its Wi-Fi radio (about 0.45 MiB/s even from a computer on the same network), not the installer.
- **Battery:** the screen shows the battery level and whether it is charging; **while installing, the bottom screen goes dark after 15 s without input and the top one after 90 s**; any button or touch wakes them (that press does nothing else), and the top screen keeps a "B: Cancel" hint. Create `config/keep-screens-on` to keep them lit.
- **HOME / sleep** are disabled while installing (opening HOME mid-install froze the console). The QR camera now stops when the app is suspended and no longer restarts by itself, which had made the HOME menu slow after an install.
- Test builds carry a tag (shown in the header) so they cannot be confused with releases.

## 1.8.1 — installer fixes
- **QR scanner:** the camera preview was upside down; fixed.
- **Installer:** data is now handed to the system's installer in 128 KiB blocks (like FBI does), instead of the 16 KiB pieces a download delivers, which the system refused on a large streamed install. **Speed:** the install no longer redraws the screen for every piece received (a few times a second instead), and the download asks for a bigger TCP receive window; the log now says the average speed and how long the system spent inside its writes. Every installer failure is now written to the activity log with its stage and result code (starting the install, each write, finishing, a size that differs from the header), so a refusal can be diagnosed.

## 1.8.0 — CIA installer (3DS) and DSi updates
- **Installer (3DS).** A new **Installer** entry in the main menu installs CIA files without FBI, four ways: from the SD card (a file browser), by typing a URL, by receiving one from the browser, and by scanning a QR code. Before anything is installed the console shows what it is (title ID, version, size, where it goes) and waits for A. What it adds over a plain installer: it checks the size the CIA header describes, checks a SHA-256 before finishing when the source gives one (a mismatch installs nothing, because the install is only committed after the check), verifies the HTTPS certificate (with the embedded Mozilla CA bundle; plain `http://` still works for a computer on your network), shows the SHA-256 it computed, warns in red about titles that go to system memory, and refuses firmware titles and NSD Bridge itself (that goes through Updates). An already-installed title is removed first, the way FBI does it, so the same or an older version can be reinstalled. Not done yet: tickets, `.3dsx`, seeds for the newest eShop titles, and managing installed titles.
- **Install CIA on the web page.** A button next to Upload (3DS only): pick a CIA on this computer (it is uploaded, checked against its SHA-256 by the console, then installed from the card), paste a URL, or install the `.cia` selected in the file list. The console only takes the request while its Installer > *Receive from the browser* screen is open, and its owner confirms there.
- **`ndev install <ip> <file.cia | url>`** replaces FBI's `servefiles.py`: it serves the file from your computer (with Range support, for the console's probe), sends the URL and the file's SHA-256, and exits when the download finishes.
- **Protocol:** new command `INSTALL_URL` (0x0040): a `url` or the `path` of a `.cia` already on the card, plus an optional `sha256`. See docs/protocol/ndp-v1.md.
- The HOME-button text now reads `NSD Bridge vX.Y.Z - SD bridge`.
- New third-party component: quirc (ISC), see NOTICE. The installer's design was informed by reading FBI (MIT).
- **DSi updates.** The DSi cannot update itself (its Wi-Fi has no HTTPS, which GitHub requires), so a computer does it: `ndev update <console-ip>` downloads the newest DSi build from the latest release, checks its size and the SHA-256 GitHub reports for it, and sends it to `/nsd-bridge/nsd-bridge-dsi-vX.Y.Z.nds` (it never overwrites, and needs DEVELOPMENT mode: press X on the DSi); then you launch the new file from TWiLight Menu++. `--file` sends a local build instead; on a 3DS the command just points to its Updates menu.
- **The web page tells you about new versions.** When the console runs an older version than the latest release, a banner shows on the page: for a DSi it gives the exact `ndev update <ip>` command (with a Copy button); for a 3DS it says to open Updates in the menu. The page asks GitHub itself (`api.github.com`, at most every 6 hours, cached; GitHub's file downloads send no CORS headers, which is why the page cannot fetch the build). It can be turned off in Settings (*Tell me about new versions*). The console's content-security policy now allows `connect-src https://api.github.com` for this.
- Host test agent: `--platform NAME`. New tests: release parsing and download checks (TypeScript), `ndev update` against the real agent pretending to be a DSi, and the page's version logic.

## 1.7.1 — the browser no longer needs pairing
- **The web page needs no pairing by default** (3DS and DSi). Open the address on the console's top screen and it connects. Pairing stays mandatory for the CLI and the MCP server (the TCP port, unchanged), and the console's own controls still gate everything dangerous: the app starts READ-ONLY, writing needs X plus a folder opened for writing, protected zones stay unwritable, and a page connection cannot see or forget the paired computers. To make the browser pair again, create `config/require-web-pairing` on the SD card. The top screen shows which mode is active. SECURITY.md and the in-page FAQ describe the trade-off. On the 3DS the on-console menu groups pairing under **Pairing**: *Pair a device*, *Paired devices* (each computer can be unpaired one at a time, or all at once) and the *Web page* on/off switch, which frees a row in the main menu; B goes back one screen. Tested against the real host agent (an open page connects as auth "none" and lists files, cannot list or forget pairings, and the raw TCP port still answers UNAUTHORIZED to an unpaired client).

## 1.7.0 — new 3DS interface and self-update
- **New on-console interface (3DS).** FBI-style: a status screen on top (state, address, mode, who is connected, the pairing number in large type) and a selectable menu on the bottom screen that works with the D-pad **and touch** (tap a row to select it, tap it again to run it, so a stray touch never exits or changes the mode). The old physical shortcuts (A, X, Y, R, SELECT, START) still work. The folder editor and the activity log are now screens of that menu, with touch and drag-to-scroll. Text follows the console's language (English or Português do Brasil). The previous text interface still builds with `NDEV_TEXT_UI=1`.
- **Self-update (3DS).** A few seconds after the network is up, the app asks GitHub for this project's latest release; if it is newer, the first menu row offers to install it. Nothing installs without you pressing that row. It uses HTTPS with an embedded Mozilla CA bundle, only downloads files from this repository's `releases/download/` path, and checks the SHA-256 and size GitHub reports for the file; the CIA installs over the existing title, a `.3dsx` is replaced with a backup. Download and install run on a worker thread, so the bridge keeps answering. Create a file named `no-update-check` in `/3ds/nintendo-dev-agent/config` to turn the automatic check off (the menu entry still works). See SECURITY.md for the limits.
- The app is bigger (about 1.3 MB instead of 0.4 MB) because it now carries libcurl, mbedTLS and the CA bundle. New build requirements: the devkitPro packages `3ds-curl 3ds-mbedtls 3ds-zlib 3ds-jansson`.
- The DSi build is functionally unchanged (its version number follows the shared core). It cannot self-update: DSi Wi-Fi has no HTTPS, which GitHub requires; update it over the bridge as before.

## 1.6.0 — DSi platform support
- **New platform: Nintendo DSi** (`agent/dsi`, BlocksDS/Wonderful Toolchain). Full feature parity with the 3DS agent on real hardware: the NDP protocol (read/write/list/stat), code-based and number-comparison pairing, the two-screen colored status UI with an activity log, the on-console folder access editor (**A**), the embedded web page, SD card free-space reporting, and a Wi-Fi network menu (**L**) that remembers up to 5 networks and reconnects on its own if the link drops. Wireless build updates over the agent's own `FS_WRITE` mean no physical SD-card swapping to iterate.
- Two real bugs found on real hardware, fixed in **shared** code (`agent/posix`), so the 3DS agent benefits too:
  - `ndp_posix_fs.c`: `lstat()`→`stat()` aliasing and the FAT symlink-containment bypass were only guarded for `__3DS__`, not the DSi's `__NDS__`, so `FS_WRITE`'s parent-directory check failed with a false `NOT_FOUND`.
  - `ndp_server.c`: `poll()` on this platform's dswifi/lwIP can permanently stop reporting a socket `POLLOUT`-ready once it has already been written to once outside of `poll()`'s own bookkeeping — silently stalling any multi-frame transfer (a file read, the web page's body) past its first chunk. Fixed generally: output is no longer gated on `POLLOUT` at all, which is free when idle and a no-op change on platforms where `POLLOUT` already worked (3DS, host).
- The web page's copy was hardcoded for the 3DS (paths, button names, a Wi-Fi speed figure, a 3DS-CFW-specific troubleshooting note) despite being served by both agents from the same bundle. It now picks a `<key>.<platform>` override via the HELLO response's platform field when one exists, falling back to the original text otherwise — covering the FAQ, the pairing screen, and a few status messages.
- Publisher branding in both agents is now "BC Labs" (was "BC Estrategias"; the DSi build had never set one, so BlocksDS's own project URL leaked into TWiLight Menu++ / flashcart loaders).
- Known DSi limits: no firmware version or system/app memory reporting (bare-metal homebrew, no OS to ask); Wi-Fi transfers run at ~0.15–0.2 MiB/s (slower than the 3DS's ~0.6–1 MiB/s); an R4i Gold flashcart's own loader fails to associate to Wi-Fi (SD access and the network scan both work) on both a DSi and a DS Lite — untested on other flashcart brands.

## 1.5.0 — paired devices management
- **View and remove paired devices** on the Settings page: a new card lists every computer or browser paired with the console, even ones not connected right now, and lets you forget any of them from the page. Two protocol commands, `PAIR_LIST` and `PAIR_FORGET` (spec-compatible additions, existing clients unaffected): any authenticated device may list and prune the console's full pairing list, mirroring the trust an opened folder already grants and the SELECT×2 "forget all" already on the console. `ndp_keystore_remove` compacts the on-console key store in place (file format unchanged). Covered by new C unit tests and a TypeScript integration test against the real host agent binary over TCP (pair two devices, list, cross-device forget, revocation on the next connection, self-forget without dropping the live session).

## 1.3.0 — first release with the web page
(1.2.0–1.2.2 were test builds that were never published; everything below is new in this release.)
- **Web page served by the console.** The 3DS app serves a file manager on port 8080 (address on the top screen; **R** turns it off/on): browse the SD card, view images, edit text files (atomic save, optional `.bak`), **drag and drop** files and folders to upload (SHA-256 checked by the console, conflict handling), download, plus Settings (device, SD and memory, opened folders, pairing, preferences) and an FAQ with the local MCP install steps. Portuguese and English, light/dark, phone friendly (one tap opens folders; checkboxes select). Same pairing, modes and folders as the CLI: the page cannot change any of them.
- **Organize:** checkbox selection, cut / copy / paste, *Move to…* / *Copy to…* with a folder picker, drag onto a folder to move, keyboard shortcuts, a **Trash** shortcut, restore, and **Delete forever / Empty trash**.
- New commands: `FS_RENAME` (0x0032, `ndev mv`, MCP `nintendo_fs_move`), `FS_PURGE` (0x0034, `ndev purge`; deletes for good but **only inside a trash**, in batches, DEVELOPMENT mode; not exposed through the MCP), `FS_COPY` (0x0035, `ndev cp`; the console copies one file in bounded steps and renames it into place, never overwrites; folders are copied file by file by the page).
- NDP over WebSocket (spec §15) with Host/Origin checks against DNS rebinding and cross-site use; the raw NDP client and the page are independent, so the MCP server keeps working while the page is open. Two tabs no longer fight over the connection (the replaced one is told, WebSocket close 4001).
- **The pairing store never says "full":** it now holds 8 pairings, a new pairing with the same name (the same browser pairing again) replaces its old key, and when it is full the oldest one is dropped (the console names it in the prompt before you press A). Before, a full store refused everything until SELECT×2 wiped all of them.
- **Pairing by number comparison** (`PAIR_BEGIN`/`REVEAL`/`POLL`): press Y on the console, click *Pair* on the page (or run `ndev pair`), and press **A** on the console when both screens show the same 6-digit number. No code to type. X25519 + a commitment (so the number cannot be ground by an attacker); the key never crosses the network. Implemented three times (C, TypeScript with node:crypto, the page in BigInt JavaScript) and checked against RFC 7748 and an independent Python reference. The 16-character code still works (`ndev pair --code`).
- The page ships its own SHA-256/HMAC (plain `http://` has no `crypto.subtle`), verified against the same test vectors as the C and TypeScript implementations. A refused stored key is no longer deleted from the browser; the pairing code field formats itself and pairs as soon as it is complete.
- Large downloads are assembled in 8 MiB blocks (the browser can keep them on disk) with a percentage; uploads warn about files of 4 GiB or more (FAT32) and about not enough free space.
